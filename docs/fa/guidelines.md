# Advery Reviews — راهنمای توسعه

## سازگاری
- وردپرس ۶ و ۷، تست تا ۷.۱. PHP نسخه‌ی ۷.۴ به بالا (بدون سینتکس/امکاناتِ جدیدتر از ۷.۴؛ nullsafe/enum/named-args استفاده نمی‌شود).
- بدون وابستگیِ سخت به Composer، WooCommerce، Elementor یا Advery Schema Plus — همه اختیاری و با feature-detect. در نبودشان هرگز fatal نشود.

## معماری و کد
- اتولودِ PSR-4 زیرِ `Advery\Reviews\`؛ یک کلاسِ کوچکِ تک‌مسئولیت در هر فایل، هم‌ساختار با هسته.
- ادمینِ React با `@wordpress/scripts` ساخته می‌شود؛ پوشه‌ی `build/` کامیت می‌شود تا بدون مرحله‌ی build اجرا شود. فرانت با CSS/JS ساده (بدون فریم‌ورک).
- مهاجرتِ نسخه‌دارِ DB با `Installer::DB_VERSION` + `maybe_upgrade()`؛ هر تغییرِ اسکیما نسخه را بالا می‌برد و افزودنی/`dbDelta`-safe است.
- برای هر نقطه‌ی توسعه اکشن/فیلتر بده؛ در architecture.md مستند کن.

## امنیت
- بررسیِ capability (`manage_options` برای ادمین، cap مناسب جاهای دیگر) و nonce روی هر تغییرِ وضعیت.
- همه‌ی SQL با `$wpdb->prepare`؛ هرگز ورودیِ نامعتمد را درج نکن.
- escape روی خروجی (`esc_html`/`esc_attr`/`esc_url`/`wp_kses_post`)؛ sanitize روی ورودی.
- REST: `permission_callback` صریح؛ اندپوینت‌های عمومی nonce-guard و محدودشده‌ی نرخ.
- رازها (کلیدهای AI، رازهای CAPTCHA) فقط سمتِ سرور؛ هرگز در فرانت localize یا از REST برنگردان.

## داده و حریمِ خصوصی
- حداقلِ لازم را ذخیره کن؛ IP فقط برای ضداسپم. مسیرِ export/delete برای درخواست‌های GDPR فراهم کن.
- منشأِ داخلی (`origin`) هرگز عمومی نمی‌شود، ولی برای یکپارچگیِ مالک وجود دارد — نه برای فریبِ ثالث.

## انطباق (قواعدِ سخت)
- هیچ فیچری نباید نظراتِ جعلی را به‌عنوانِ واقعی به عموم یا در اسکیما نمایش دهد. محتوای نمونه/دمو آشکارا برچسب‌خورده و به‌طور پیش‌فرض بیرونِ `aggregateRating` است.
- نظراتِ third-party فقط با حقِ استفاده (داده‌ی خودِ مالک از راه APIهای رسمی) ایمپورت و attribution می‌شوند؛ وارد `aggregateRating` شما نمی‌شوند مگر مالک/جمع‌آورنده باشید.
- AI هرگز محتوای عمومی را بدونِ تأییدِ مالک یا حالتِ خودکارِ صراحتاً‌فعال‌شده منتشر نمی‌کند، و همیشه با سقفِ هزینه/نرخ و لاگِ حسابرسی.

## فرایند
- ساخت → تأییدِ زنده روی سایت نمونه → به‌روزرسانیِ چنجلاگِ **دوزبانه** (docs/en + docs/fa) → تگ + GitHub release با فایلِ zip.
- تصمیم‌های تغییریافته و اشتباه‌ها را در changelog_and_logs.md ثبت کن تا تکرار نشوند.
